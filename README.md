# Akib Ahmed — Portfolio

A production-oriented personal portfolio for **Akib Ahmed**, a software engineer working across full-stack development, DevOps, and QA automation.

The design is an editorial **Amber Minimal** system: oversized condensed typography, an asymmetric multi-panel hero, warm paper surfaces, thin rules, and amber used only for emphasis. It is deliberately not a generic developer template.

## Stack

- **React 19 + TypeScript + Vite 7**
- **React Router 7** for real routes and browser history
- **Express 4** serving the SPA, SEO endpoints, and the contact API
- **Zod 4** with one validation schema shared by the browser and server
- **Nodemailer** for optional SMTP notifications
- Self-hosted **Inter**, **Anton**, and **JetBrains Mono** fonts
- Hand-built inline SVG architecture diagrams (no stock screenshots)
- Vitest for unit and content-integrity tests

## Run locally

Requires **Node.js 20.19+** (tested on Node 24).

```bash
npm install
npm run dev
```

Open **http://127.0.0.1:3000**. Express runs Vite in middleware mode, so HMR and the API share one port.

Production:

```bash
npm run build
npm start
```

`npm start` sets `NODE_ENV=production` through `server/start.ts` (cross-platform), serves `dist/`, and requires a build first.

## Configure your details

Content is separated from presentation under `src/content/`.

### `src/content/profile.ts`

- `name`, `role`, `disciplines`, `intro`
- `availability.available` / `label` / `detail` — controls the status pills across the site
- `location`, `timezone`, `workPreference`
- `education` — only verified details; institution is intentionally left to “available on request”
- `email` — **currently `null`**. Set it to a real address to enable mailto links and the direct-email fallback in the footer/about/contact pages.
- `links.github`, `links.linkedin`, `links.upwork` — **currently `null`**. Set each to a full URL. No URLs were guessed or invented.
- `portrait` — **currently `null`**, so the site uses a deliberate typographic `AA` plate. To use a real portrait, place a file in `public/` and set the path (for example `'/portrait.jpg'`).

Social links and the email fallback are hidden until they are configured. This is intentional: the alternative would be publishing links or an address that do not belong to Akib.

### `src/content/projects.ts`

Three case studies with problem, requirements, architecture, implementation, API/security, testing, delivery, and lessons sections. All repository and demo links are `null` because the repositories are private; the UI says so explicitly and the content makes no production-metric claims. Add `repo`/`live` URLs only when they actually exist.

### `src/content/skills.ts`

Four capability groups. The copy describes a working toolkit rather than claiming mastery of every item. Adjust both `skillGroups` and the short `heroSkills` list in `src/pages/Home.tsx` as needed.

### Resume PDF

`public/akib-ahmed-resume.pdf` is a static snapshot generated from `/resume`. If profile content changes, open `/resume`, choose **Print**, and save a new A4 PDF over that file (or use the on-page print button). The resume page is print-optimized: navigation, footer, and controls are removed from the printed output.

## Contact form

The form posts JSON to `POST /api/contact` and never shows success before the server accepts the message.

Server behavior:

1. Rejects non-JSON requests (`415`) and mismatched browser origins (`403`).
2. Applies an in-memory rate limit of **8 submissions per 15 minutes per IP** (`429` with `Retry-After`).
3. Silently drops honeypot submissions.
4. Validates with the same Zod schema the browser uses.
5. Appends the submission to `data/contact-submissions.jsonl` with file mode `0600`.
6. Optionally sends an SMTP notification. Email failure does **not** discard the stored message.
7. Returns a reference ID used in the success state.

Read stored messages locally:

```bash
npm run messages
```

### Required/recommended environment

Copy `.env.example` to `.env` (ignored by git):

| Variable | Required | Purpose |
| --- | --- | --- |
| `SITE_URL` | Recommended | Public origin for canonical sitemap/robots URLs (for example `https://example.com`) |
| `PORT` | No | Defaults to `3000`; invalid/zero values fall back to `3000` |
| `HOST` | No | Defaults to `127.0.0.1` in development and `0.0.0.0` in production |
| `TRUST_PROXY` | Behind proxy | Set to `1` so rate limiting sees the client IP |
| `DATA_DIR` | No | Defaults to `./data`; use a persistent disk in production |
| `CONTACT_TO_EMAIL` | For email | Private inbox that receives notifications |
| `SMTP_HOST` | For email | SMTP server hostname |
| `SMTP_PORT` | No | Defaults to `587` |
| `SMTP_SECURE` | No | Set `true` for implicit TLS (usually port 465) |
| `SMTP_USER`, `SMTP_PASS` | Usually | SMTP credentials; keep them in the host’s secret store |
| `SMTP_FROM` | No | From header for notifications |

Without SMTP, submissions are still accepted and stored; only the notification email is skipped. Configure `profile.email` separately if you want a visible direct-email fallback.

## Deployment notes

- This is a **Node server deployment**, not a static-only build. Netlify/Vercel static hosting would not run the contact API without adapting it to their function model.
- Build with `npm run build`, then run `npm start` from the project root.
- Give the service a writable, persistent `DATA_DIR`. Ephemeral filesystems will lose stored messages.
- Put HTTPS and a reverse proxy in front of the server, then set `SITE_URL` and `TRUST_PROXY=1`.
- Production sends a strict CSP, `X-Content-Type-Options`, frame denial, Referrer Policy, Permissions Policy, and HSTS when `SITE_URL` is HTTPS.
- The rate limiter is process-local. A multi-instance deployment needs a shared store (Redis or similar).
- Review the availability flags and content in `src/content/` before publishing.

## Quality checks

```bash
npm run typecheck
npm test
npm run build
npm run check   # typecheck + tests + build
```

The test suite covers contact validation and field-error mapping, rate-limit windows, HTML escaping in notification email, project filters/search/adjacency, and content integrity. Browser verification covered all nine routes at 390, 834, and 1440 px with no horizontal overflow, broken images, or console errors, plus axe WCAG 2.1 A/AA scans at every viewport. Interaction checks covered mobile navigation (including Escape and focus return), filters and deep links, form validation/success/failure, server persistence, keyboard skip-link behaviour, success focus management, reduced motion, production 404s, security headers, CSP, and the PDF. SMTP delivery was also verified locally with a mail catcher.

## Accessibility, SEO, and performance

- Semantic landmarks, a skip link, one `h1` per page, visible focus states, keyboard-operable controls, and `aria-live` result counts.
- Contact errors link to fields through `aria-describedby`; the failure state is announced with `role="alert"`; success is a focused status panel.
- `prefers-reduced-motion` disables the page-entry animation and transitions.
- Route-specific titles, descriptions, canonical URLs, Open Graph/Twitter metadata, a Person JSON-LD block, sitemap, robots, and noindex 404s.
- Route-level code splitting keeps the initial JS around **101 kB gzip**; the contact route (with Zod) is a separate chunk. The CSS is about **10 kB gzip**.
- Fonts are self-hosted and subset by unicode range; diagrams are inline SVG.
- Unknown production routes return HTTP 404 (with the styled not-found page) rather than a soft 200.

2. **No portrait supplied.** The monogram plate is a deliberate fallback, not a fake person.

4. **SMTP is not configured in this checkout.** The form stores submissions; email delivery needs the SMTP variables above. The SMTP path was verified locally with a mail catcher, not with a live provider.
5. **Single-instance rate limiting** (in-memory) and **file-based storage** (JSONL) are appropriate for a portfolio, not a multi-node service.
6. **Resume PDF is a snapshot.** Regenerate it after changing profile/project content.
7. No automated visual-regression suite is included; responsive checks were run through a real Chromium browser at 390, 834, and 1440 px.
